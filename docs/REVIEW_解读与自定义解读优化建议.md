# 解读 / 自定义解读 功能、交互、UI 优化建议

> 评审对象：`解读`（选区工具条「解读」按钮 → 单条解释会话）与 `自定义解读`（右侧面板暂存区 → 多片段组合解读）
> 依据代码：`SelectionToolbar.tsx` / `usePersistence.ts`（`handleSelectionAction`、`startSessionFromStashes`、`handleCustomInterpret`、`runSessionStream`）/ `ExplainPopup.tsx` / `StashInterpretedPopup.tsx` / `CustomInterpretModal.tsx` / `AiChatPanel.tsx` / `PdfAnnotations.tsx` / `TranslatePopup.tsx` / `services/llm.ts`
> 结论先说：**两条链路都已能跑通且工程完成度高**，但「结果离用户当时阅读的上下文太远」是核心体验短板，且「解读」与「翻译」在 popup 能力上严重不对称。

---

## 一、现状速览

| 维度             | 解读（explain）                                      | 自定义解读（custom）                                                                        |
| ---------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 触发             | 选区工具条「解读」                                   | 右侧面板「暂存」tab → 自定义解读                                                            |
| 结果落点         | 右侧面板新建会话（session）                          | 右侧面板新建会话（session）                                                                 |
| 页面标记         | 蓝色 `explain` 标记                                  | 蓝色「已解读暂存」标记（`stash` + `interpretedGroupSize`）                                  |
| 标记点击弹层     | `ExplainPopup`：仅显示**原文** + 「查看解读 / 删除」 | `StashInterpretedPopup`：仅显示**原文** + 「查看解读 / 删除」                               |
| 看到结果所需操作 | 标记 → 弹层 →「查看解读」→ 跳右侧面板                | 选片段 → 暂存（选区工具条）→ 去面板 →（选择模式）→ 自定义解读 → 填 prompt → 发送 → 右侧面板 |
| Agent Tools      | 启用（explain/custom 且平台支持）                    | 启用                                                                                        |
| 重跑/再生        | 需删除标记后重新选区                                 | 源暂存片段被**消费删除**，不可直接重跑                                                      |

**最关键的观察**：`TranslatePopup` 会在标记处**内联流式**渲染翻译结果（含 loading spinner、error、Markdown），而 `ExplainPopup` / `StashInterpretedPopup` 只显示原文，结果必须跳到右侧面板——同一套标记交互，能力却不对称。

---

## 二、功能层面（Functionality）

### F1. 解读结果不回显到页面，且无法「重新解读」

- 现状：`ExplainPopup` 的 `explain-popup-body` 只渲染 `annotation.text`（原文），无 AI 输出、无「重新生成」入口。要看结果必须「查看解读」跳面板。
- 建议：把 `TranslatePopup` 的内联渲染模式复制到解读标记——标记点击后直接展示解读结果（Markdown + 流式/错误态），并加「重新解读」按钮（`runSessionStream` 已可复用，只是目前入口在面板）。这样解读与翻译体验一致，且不离阅读位置。

### F2. 自定义解读「消费并删除」源片段，不可重复利用

- 现状：`handleCustomInterpret` 发送后 `setStashes(prev => prev.filter(...))` 直接移除参与片段；`handleClearStashes`、退出选择模式也都只做减法。
- 问题：想对同一批条款做第二次不同角度的解读（如先「提炼测试步骤」再「对比两版差异」），只能重新选区、重新暂存。标准工程师常对同一批条款反复追问。
- 建议：解读后保留源暂存（仅打 `interpretedGroupSize`/关联 `sessionId` 标记），或在会话里提供「复制结果为新暂存」；删除解读时给「仅删结果 / 连片段一起删」两个选项。

### F3. 缺少「整页 / 整节 / 按大纲章节」解读

- 现状：解读粒度只有「选区文本」和「暂存组合」，无按页、按 outline 条目的入口。
- 建议：选区工具条或页面右键加「解读本页」「解读本章节」，利用已有 `read_pdf_page` / outline 数据一次性发起，契合标准「逐条理解条款」的真实工作流。

### F4. 无去重 / 「已有解读」提示

- 现状：同一段文本重复点「解读」会新建多条 session（`startSessionFromStashes` 每次 `createSession`）。
- 建议：按 `(fileHash, page, text)` 做幂等检查，若已有该片段的解读会话，弹层直接「跳转到已有解读」而非新建；或在该标记上显示「已解读」角标。

### F5. 自定义解读 Prompt 无模板 / 快捷指令

- 现状：`CustomInterpretModal` 只有空白 `textarea` + placeholder，对新手门槛高。
- 建议：内置一组面向检测认证的快捷指令（一键填入）：「提炼可执行的测试步骤」「对比两段差异」「汇总关键判定/限值」「用通俗中文解释并标注相关专业术语」「指出与其他条款的引用关系」，并保留自由输入。

### F6. 解读结果不可导出 / 整段复制，无原文锚点回跳

- 现状：会话消息是 Markdown，但无「复制全部」「导出 .md/.txt」，且从会话回到原文只有「标记 → 查看解读」单向；会话卡片本身不提供「跳转源」按钮。
- 建议：会话详情加「复制 / 导出」；每条会话头部加「跳转原文」按钮（`tabs.gotoTabPage` 已有能力，见 `App.tsx` 的 `handleGotoStash` 思路）。

### F7. 多源自定义解读在会话里「只见 prompt 不见源」

- 现状：`buildCustomInterpretPrompt` 把源片段拼进 user 消息，但 `AiChatPanel` 渲染时 `role==="user"` 只显示 `message.content`（即用户的自由 prompt），原始片段不可见、不可逐条点回。
- 建议：在 user 消息下渲染「源片段卡片」列表（文件名/页/摘要，可点跳），让解读与依据一一对应——这对标准条款溯源尤其重要。

### F8. 解读/翻译/批注无法沉淀为「笔记/知识库」

- 现状：三者都是临时标记 + 会话，关闭 PDF 后靠本地文件留存，但无结构化的「我的解读笔记」聚合视图。
- 建议（远期）：提供跨 PDF 的解读笔记汇总/检索，呼应 AGENTS.md 已规划的 Clause 索引与术语表方向。

## 三、交互层面（Interaction）

### I1. 看结果要「跳两次」，且与翻译不一致（P0）

- 现状：解读标记点击 → 弹层 →「查看解读」→ 右侧面板；且点击「查看解读」会 `setOpenPopupId(null)` 关掉原文弹层，跳转后**上下文丢失**。
- 建议：标记弹层直接内联结果（F1），「查看解读」改为「在面板展开全文/追问题」，跳转时**保留**原文弹层或把它降级为常驻小标。与 `TranslatePopup` 对齐。

### I2. 自定义解读步骤过多（P0）

- 当前链路：选区 → 暂存 → 去右侧面板 →（进入选择模式勾选）→ 自定义解读 → 填 prompt → 发送，至少 5 步且跨左右两栏。
- 建议：
  - 选区工具条直接加「自定义解读所选」入口（选区时若已选多段，或先多选几个片段后再发起），合并「暂存 + 发起」；
  - 或在选区后弹出轻量面板，直接勾选本次要纳入的片段 + 填要求 + 发送，不必先落暂存区。

### I3. 选择模式下的信息缺失

- 现状：进入选择模式后点击文本=切换选中，但**没有实时预览「将包含哪些片段」**；退出模式才能点文本回跳。
- 建议：选择模式下每个片段卡显示序号/来源，顶部显示「已选 N / 共 M」，并允许在卡片内直接取消勾选（不依赖右侧 checkbox 位置）。

### I4. 生成中无页面内反馈（P0）

- 现状：点「解读」后只有右侧面板被 `openRightPanel()` 打开；若面板已折叠或被用户忽略，页面标记上无任何「生成中」状态。
- 建议：在标记上加「生成中」态（呼吸/ spinner，类似 `TranslatePopup` 的 `translate-popup-loading`），让用户在当前阅读位置就能感知进度。

### I5. 会话 → 原文单向，回跳不便

- 现状：标记可跳会话，但会话卡片无「回到原文」入口（`handleGotoStash` 已存在却未接到会话头部）。
- 建议：会话详情头部加「跳转源」按钮，支持多源时列出多个可点项。

### I6. 流式追问题时回车被吞，无提示

- 现状：`FollowUpInput` 在 `isStreaming` 时忽略 Enter（注释说为避免误触中断），但用户只看到「发不出去」，不知要点「中止」。
- 建议：生成中把发送按钮明确置为「中止」态并给 tooltip；回车忽略时给一行轻提示（如 toast「生成中，点此中止」）。

### I7. 删除级联缺少选项

- 现状：`handleAnnotationDelete` 对 `explain` / 已解读暂存删除会连带删 session（且弹确认框）。用户可能只想删「结果」保留「片段」。
- 建议：确认框给「删除解读结果」「同时删除源片段」两个动作。

## 四、UI 层面（UI）

### U1. 解读弹层与翻译弹层视觉/能力不对称（P0，核心）

- `TranslatePopup`：内联结果 + loading + error + 可拖拽 + 隐藏/关闭。
- `ExplainPopup` / `StashInterpretedPopup`：仅原文 + 两个按钮，且共用 `explain-popup` 样式、宽度 280、body `max-height:200` 只够显示原文。
- 建议：统一为「结果预览（Markdown，可滚动）+ 原文折叠 + 操作（重新解读 / 跳转 / 删除）」一套组件，消除两类标记体验割裂。

### U2. 两种标记视觉语义相同

- 现状：`explain` 标记与「已解读暂存」标记都是蓝色，hover/常态无区分；且 `ExplainPopup` 与 `StashInterpretedPopup` 组件几乎重复。
- 建议：用图标/颜色区分「单条解释」与「多片段组合解读」；两个 popup 合并为一个参数化组件减少维护成本。

### U3. 会话卡片信息过简（P0/P1）

- 现状：会话列表项只显示 `session-item-source`（文件名·页）和最近一条 user prompt（截断 80 字），无类型、模型、耗时/token、状态徽章。
- 建议：加类型徽章（解读 / 自定义解读）、来源片段数、token 用量（`lastPromptTokens` 已有）、流式状态；可按 PDF 分组或加搜索过滤。

### U4. 面板双 tab 查找成本高

- 现状：暂存与解读会话分属 `stash` / `sessions` 两个 tab，解读结果散落在 sessions，与暂存取在同一面板的不同 tab。
- 建议：考虑「按当前 PDF 聚合的时间线」或至少在 sessions tab 顶部提供「当前文档 / 全部」过滤，减少跨 tab 来回。

### U5. 自定义解读弹窗无片段预览（P0）

- 现状：`CustomInterpretModal` 仅显示 `count`，不列出将参与的片段。
- 建议：弹窗内渲染片段清单（文件名/页/摘要，可勾选/取消），并把「选择模式」前置到弹窗，省去先回面板进选择模式的多余步骤（呼应 I2）。

### U6. 长文阅读体验

- 建议：会话结果区加「复制 / 全屏阅读 / 字号」，窄面板下长解读更易读。

### U7. 深色适配（轻）

- 当前 `AiChatPanel.css` / `ExplainPopup.css` 写死浅色（`#fff`/`#fafafa`）。若后续支持深色主题需统一变量；当前 Tauri 桌面端为独立浅色皮肤，可视情况忽略。

## 五、优先级建议

**P0（体验杠杆最大、成本可控，建议优先）**

1. I1 + U1 + F1：解读标记内联结果 + 与翻译弹层统一组件（消除不对称、免去跳两次）。
2. I4：标记「生成中」状态反馈。
3. I2 + U5：自定义解读「选区直达 + 弹窗内片段预览/勾选」，砍掉多余步骤。
4. U3：会话卡片加类型/状态/来源徽章，降低结果查找成本。

**P1**

- F2 保留源暂存、删除级联给选项（I7）
- F4 去重 / 已有解读提示
- F5 自定义解读快捷指令模板
- I5 会话回跳原文
- F7 会话内源片段卡片

**P2**

- F3 整页/整节解读
- F6 导出/整段复制
- I6 追问题回车提示
- F8 解读笔记/知识库沉淀

## 六、最小可行性改造路径（参考）

1. 把 `TranslatePopup` 的内联渲染骨架抽成可复用 `<InlineResultPopup>`（结果/loading/error/拖拽/操作），`ExplainPopup` 与 `StashInterpretedPopup` 改为其特化，补「重新解读」「跳转」「生成中」三态。
2. `CustomInterpretModal` 改为接收 `stashes` 列表，内部渲染可勾选片段 + 快捷指令按钮，提交即发起；`SelectionToolbar` 增加「自定义解读所选」直接调起该弹窗并预填当前选区。
3. `AiChatPanel` 会话卡片与详情头部补充类型徽章 + 「跳转源」按钮（复用 `handleGotoStash` 思路）。
4. `handleCustomInterpret` 改为「保留源暂存、仅打标关联」，删除路径新增「仅删结果」选项。

以上改动均落在现有状态/服务边界内，不破坏已有的按 `fileHash` 持久化与 Agent Tools 机制。
