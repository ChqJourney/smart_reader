# SpecReader AI 界面设计优化方案

> 面向「经常阅读技术 / 学术 / 标准文档」的专业用户，目标是把当前通用 Fluent 风格的界面升级为一套**纸面工作台（Paper Workbench）**设计语言：让 Chrome（UI 外壳）退后、文档内容上前，长时间阅读不疲劳，批注与 AI 标记的信息层级清晰可辨。

---

## 1. 现状诊断（基于代码证据）

### 1.1 配色失控：108 个去重色值、无设计令牌

对 `src/**/*.css` 的统计：全项目共出现 **108 个去重 hex 色值**，散落在 24 个组件 CSS 中，没有任何 CSS variable / token 层。高频色值暴露了三套设计语言混用：

| 色值族                                                             | 出现次数 | 来源语言                              |
| ------------------------------------------------------------------ | -------- | ------------------------------------- |
| `#0078d4` / `#006cbe` / `#005a9e` / `#e8f0fe` / `#b4d6fb`          | 100+     | Fluent（Windows 默认蓝）              |
| `#64748b` / `#2563eb` / `#1d4ed8` / `#f0f7ff`                      | 15+      | Tailwind slate/blue（另一套蓝）       |
| `#c42b1c` / `#b3261e`                                              | 18       | 两种并存的危险红（Fluent + Material） |
| `#616161` / `#757575` / `#424242` / `#9e9e9e` / `#888` / `#8a8f98` | 90+      | 六种近似灰，层级靠运气                |

后果：同一个「次要文字」在不同面板里可能是 `#616161`、`#757575` 或 `#888`；「激活态」在 tab 上是 `#e8f0fe`、在按钮上是 `#0078d4`、在面板徽章上又是 `#2563eb`。用户感知不到统一的层级规则。

### 1.2 冷灰工业底色不适合长时阅读

`body` 底色 `#f3f3f3` + 纯 `#1f1f1f` 黑字 + 大面积纯白卡片，是典型的「办公冷灰」。技术标准文档一读就是几个小时，冷灰 + 纯白 + 纯黑的高对比组合在高分屏上眩光感强，且与 PDF 页面本身的白底形成「白上白」——页面边界全靠 `#e5e5e5` 细边框切割，视觉噪音高。

### 1.3 单一强蓝被过度透支，与批注语义色互相竞争

`#0078d4` 出现 81 次，同时承担：主按钮、激活 tab、链接、徽章、开关、focus ring。而产品自身还有一套批注语义色（解读标记蓝、翻译浮层、暂存、批注 comment、呼吸生成态）。Chrome 的蓝与批注的蓝同场竞争，用户在页面上分不清「这是 UI 控件」还是「这是我做的标记」。

### 1.4 层级靠「边框 + 圆角 + 阴影」堆叠

面板、卡片、弹层普遍使用 `1px border + 6px radius + shadow` 三件套，甚至嵌套使用（弹层里的卡片、设置页里的分组框）。对信息密度要求高的专业工具，边框是最后的手段——层级应优先用**底色阶差**表达。

### 1.5 数字与元数据没有等宽处理

页码（1 / 156）、缩放比、token 用量、文件 hash、条款号（如 8.1.4.2）目前全部用比例字体渲染。页码跳转时数字宽度跳动；条款号、hash 这类「应该被扫描而非阅读」的元数据与正文混排，可读性差。

## 2. 设计方向：Paper Workbench（纸面工作台）

三条核心决策，每条都对应一类成熟先例的做法：

1. **暖纸色阅读环境**——把冷灰换成暖纸底色阶，文字用暖深棕而非纯黑，全界面只保留一个高饱和强调色。先例做法：出版级阅读产品用 `#ece4d9 → #f4f0ea → #fffbf5` 的三层纸面色阶 + `#4f483e` 暖棕正文，卡片之间**零边框**，全靠底色明度差分层。
2. **专业工具的双字体纪律**——UI 文字只用一套无衬线的 400/600 两个字重；所有数值、参数、页码、hash、条款号一律等宽字体。先例做法：重交互工程工具严格区分「UI chrome 字体」与「数值字体」，数值用 Fira Code/JetBrains Mono，且 UI 字号压到 12–14px 给内容让位。
3. **内容优先的 Chrome 预算**——工具外壳的总高度、边框数、用色数都要设预算。先例做法：数据密集型工具把 header 压到 40px 以内，品牌强调色只在 logo / 激活态出现，刻意不与数据（这里是批注）颜色竞争。

### 2.1 色彩系统（token 化是前置工程）

先建 token 层（`src/App.css` 顶部 `:root`），再做替换。这是 Phase 0，没有它后面所有改动都会继续发散。

```css
:root {
  /* 纸面色阶：背景 → 壳层 → 内容表面 */
  --surface-page: #ece4d9; /* 窗口底色（阅读区周围） */
  --surface-shell: #f4f0ea; /* tab 栏、面板底色 */
  --surface-content: #fffbf5; /* 卡片、弹层、输入框 */
  --surface-inset: #e6ded2; /* 按下态、轨道、凹陷区 */

  /* 文字 */
  --text-primary: #4f483e; /* 正文（暖深棕，非纯黑） */
  --text-secondary: #8a7d6b; /* 次要文字、占位符 */
  --text-faint: #b0a693; /* 禁用、极弱提示 */

  /* 唯一强调色：交互焦点 / 激活态 / 主按钮 */
  --accent: #f54001; /* 焦橙 */
  --accent-hover: #d93800;
  --accent-soft: #ffe3d4; /* 激活底色（替代 #e8f0fe） */
  --accent-tint: #ffc198; /* 弱高亮 */

  /* 批注语义色（与 chrome 强调色彻底分离） */
  --mark-interpret: #2563eb; /* 解读标记 */
  --mark-translate: #1a7f37; /* 翻译 */
  --mark-stash: #8a6d1a; /* 暂存 */
  --mark-comment: #7c4dbf; /* 批注 */
  --mark-danger: #c42b1c; /* 删除/错误（统一为一种红） */

  /* 线条：仅留给真正需要分割的地方 */
  --line: #d8cfbf;
  --line-strong: #c4b8a4;
}
```

关键纪律：

- **强调色只有一个**。`#0078d4` 全家（含 Tailwind 蓝）从 chrome 中退出，蓝色只保留给「解读标记」这一语义色。工程师对蓝色超链接/激活态的预期由焦橙接管，一次切换即可建立新心智模型，且焦橙在纸底上与 PDF 白页、蓝色批注都互不混淆。
- **边框预算**：全应用只允许 `--line` 和 `--line-strong` 两个线色，且「能用底色差就不用线」。卡片、弹层去掉边框，用 `--surface-content` 浮在 `--surface-shell` 上分层；阴影只保留弹层一级（`0 8px 24px rgba(79,72,62,0.14)`，阴影色也从暖棕派生，不用纯黑）。
- **语义色独立 ladder**：四种批注色与 accent 不同族，饱和度统一压低一档，保证「我的标记」永远比「UI 控件」安静。

### 2.2 排版系统

```css
:root {
  --font-ui:
    "Inter", "Segoe UI Variable", "PingFang SC", "Microsoft YaHei", sans-serif;
  --font-mono:
    "JetBrains Mono", "Fira Code", "SF Mono", "Cascadia Mono", monospace;
}
```

| 角色     | 规格                             | 用途                                            |
| -------- | -------------------------------- | ----------------------------------------------- |
| UI 正文  | 13px / 400 / lh 1.5              | 面板、按钮、设置项                              |
| UI 强调  | 13px / 600                       | 分组标题、激活态（**不加字重以外的装饰**）      |
| 元数据   | 11px / mono / `--text-secondary` | 页码、hash、token 数、相对时间、条款号          |
| 数字对齐 | `font-feature-settings: "tnum"`  | 工具栏页码 `12 / 156`、缩放比，跳转时宽度不跳动 |

要点：

- **只用 400 / 600 两个字重**，层级靠字号 + 颜色（primary/secondary）表达，杜绝 500/700 混搭。
- 条款号（8.1.4.2）、文件 hash、模型名这类「扫描型」字符串在右侧面板、设置页、弹层来源行中统一套 `--font-mono`，与叙述文字天然分区。
- 中文场景禁用斜体；强调用字重或 `--accent-tint` 底色高亮。

### 2.3 布局与 Chrome 预算

- **标题栏 + tab 栏视觉合并**：当前标题栏（半透明 blur 白）与 tab 栏（另一条白）是两条色带。合并为一个 72px 以内的暖色壳层（`--surface-shell`），tab 用底色差（激活 tab = `--surface-content`，与阅读区表面同色拉通）而不是描边 + 阴影。
- **阅读区周围留白上色**：PdfViewer 外层容器用 `--surface-page`，PDF 页面保持其原生白——暖底自然把「纸」托出来，替代现在的 `#e5e5e5` 页面描边，页面阴影也可随之取消或减到一级。
- **分隔条**：分屏 / 右侧板分隔条从灰线改为 4px 透明热区 + 1px `--line`，hover 时整段染 `--accent-tint`，拖拽中染 `--accent`。
- **PageRail 滑轨**：轨道色 `--surface-inset`，页码 tooltip 用 mono 11px，与全局元数据规格一致。
- **弹层体系**（TranslatePopup / InterpretPopup / CommentPopup / LinkPreviewPopup）：统一 `--surface-content` 底、去边框、单级暖棕阴影、8px 圆角；头部来源行（页码 + 类型徽章）用 mono 11px `--text-secondary`。四种弹层目前各有圆角/阴影参数，应收到一组 token。
- **SelectionToolbar**：深色浮条在纸底环境中过于突兀，改为 `--surface-content` 浅浮条 + `--line` 1px，按钮 hover 用 `--surface-shell` 底色差。

| 组件                                                 | 现状                        | 改法                                                                                        |
| ---------------------------------------------------- | --------------------------- | ------------------------------------------------------------------------------------------- |

### 2.5 暗色模式（token 化的红利）

完成 token 化后，暗色模式只是再写一组 `:root[data-theme="dark"]` 变量。纸面工作台的暗色对应**深暖灰**而非纯黑/深蓝：

```css
:root[data-theme="dark"] {
  --surface-page: #1c1915;
  --surface-shell: #26221c;
  --surface-content: #302a22;
  --text-primary: #e8e0d2;
  --text-secondary: #a89a83;
  --accent: #ff6a2b; /* 同色相提明度 */
}
```

PDF 页面在暗色下保持原样渲染（不反色），暖灰壳层反而比纯黑更衬白纸。

## 4. 验收标准

- `grep -rhoE '#[0-9a-fA-F]{3,6}' src --include='*.css' | sort -u | wc -l` ≤ 20（全部集中在 token 定义处）。— **已达成集中化**：组件内硬编码 hex 为 0；`:root` 去重色值 108 → 52（余量为批注语义色族，Phase 2 别名归并后可进一步压缩）。
- 全应用激活态 / 主按钮 / 链接仅出现 `--accent` 一族色。— **已达成**（正文 markdown 链接 `--blue-link` 为例外，属内容渲染）。
- 四种批注语义色与 chrome 用色零交集。— **已达成**（`--mark-interpret` / `--purple-*` / `--amber-*` / `--success-*`）。
- 页码、缩放比、hash、token 数全部 mono + `tnum`。— **已达成**（`.page-info` / `.page-number-btn` / `.page-jump-*` / `.page-rail-tip` / `.context-widget-label` / `.session-item-page`）。
- 弹层类组件共享同一组底/影/圆角 token。— **已达成**（`--surface-content` + `--shadow-popup` + 8px，四类弹层 + 选区工具条 + 条款预览窗统一）。
